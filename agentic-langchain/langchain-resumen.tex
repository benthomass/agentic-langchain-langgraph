\begin{concept}[title=¿Qué es LangChain?]
Framework de \textbf{orquestación} para apps con LLMs: conecta modelos, prompts, tools, retrievers y memoria en \textbf{chains} (pasos fijos) o \textbf{agents} (bucle que decide tools).
No es el modelo en sí.
\end{concept}

\begin{tip}[title=Cómo correr cosas en este repo]
Usa \textbf{uv} desde \texttt{agentic-langchain/}:
\texttt{uv sync} $\cdot$
\texttt{uv run python 01-hello-world/main.py} $\cdot$
\texttt{uv run streamlit run 05-building-documentation-assistant/main.py}
\end{tip}

\section{Arquitectura mental: Chain vs Agent}
% =============================================================================

\begin{center}
\begin{tabular}{@{}p{7.4cm}p{7.4cm}@{}}
\toprule
\textbf{Chain (pipeline fijo)} & \textbf{Agent (bucle de decisión)} \\
\midrule
Tú fijas los pasos:
\texttt{retrieve $\to$ prompt $\to$ llm} & El LLM elige tools y cuántas veces \\
Ej.: RAG LCEL en \texttt{04-rag/main.py} & Ej.: \texttt{create\_agent} (02, 05);
bucle manual (03) \\
Más predecible / barato & Más flexible; más tokens / latencia \\
\bottomrule
\end{tabular}
\end{center}

\begin{lookup}[title=¿Chain o agent?]
¿Siempre recuperas $k$ docs y respondes? $\to$ \textbf{chain}.
¿Puede necesitar 0, 1 o N tools / varias queries de retrieval? $\to$ \textbf{agent}.
\end{lookup}

\section{Mensajes: el idioma de LangChain}
% =============================================================================

\begin{center}
\begin{tabular}{@{}llp{7.6cm}@{}}
\toprule
\textbf{Clase} & \textbf{Rol} & \textbf{Uso} \\
\midrule
\texttt{SystemMessage} & system & Reglas / persona del asistente \\
\texttt{HumanMessage} & user & Pregunta del usuario \\
\texttt{AIMessage} & assistant & Respuesta; puede traer \texttt{tool\_calls} \\
\texttt{ToolMessage} & tool & Resultado de tool (\textbf{lleva} \texttt{tool\_call\_id}) \\
\bottomrule
\end{tabular}
\end{center}

\begin{fromcode}[title=03/.../agent-loop-tool-calling.py]
\begin{lstlisting}
messages = [
    SystemMessage(content="You are a helpful assistant..."),
    HumanMessage(content=question),
]
ai_message = llm_with_tools.invoke(messages)
messages.append(ai_message)
messages.append(ToolMessage(
    content=str(observation), tool_call_id=tool_call_id))
\end{lstlisting}
\end{fromcode}

Forma dict (también válida; usada en 05):

\begin{lstlisting}
messages = [{"role": "user", "content": query}]
\end{lstlisting}

\begin{concept}[title=tool\_call\_id]
Enlaza cada \texttt{ToolMessage} con la petición concreta en \texttt{AIMessage.tool\_calls}.
Sin eso el historial queda ambiguo (sobre todo con varias tools).
\end{concept}

\section{\texttt{invoke}, \texttt{stream}, \texttt{batch}, async}
% =============================================================================

Casi todo ``Runnable'' expone:

\begin{center}
\begin{tabular}{@{}llp{7.6cm}@{}}
\toprule
\textbf{Método} & \textbf{Modo} & \textbf{Significado} \\
\midrule
\texttt{invoke(x)} & sync & Una entrada $\to$ una salida completa \\
\texttt{stream(x)} & sync & Chunks conforme se generan \\
\texttt{batch([...])} & sync & Varias entradas en paralelo \\
\texttt{ainvoke} / \texttt{astream} & async & No bloquean el event loop \\
\texttt{aadd\_documents} & async & Indexar docs (05 $\to$ Chroma) \\
\bottomrule
\end{tabular}
\end{center}

\begin{lookup}[title=Shape del input]
\begin{itemize}[leftmargin=*,itemsep=1pt]
  \item LLM: lista de mensajes o string
  \item Chain LCEL RAG: \texttt{\{"question": "..."\}}
  \item Agent: \texttt{\{"messages": [...]\} }
  \item Tool: dict de args (\texttt{tool.invoke(\{"product\_name": "laptop"\})})
\end{itemize}
\end{lookup}

\section{Tools: \texttt{@tool}}
% =============================================================================

\begin{lstlisting}
from langchain.tools import tool

@tool
def get_product_price(product_name: str) -> float:
    """Look up the price of a product in the catalogue.

    Args:
        product_name: The base name ONLY (e.g. 'laptop').
    """
    return prices.get(product_name, 0)
\end{lstlisting}

\begin{concept}[title=Qué hace @tool]
Función Python $\to$ Tool: nombre = función; descripción = \textbf{docstring};
schema = type hints; ejecutable con \texttt{tool.invoke(args\_dict)}.
\textbf{Docstring bueno = tool que el modelo usa bien.}
\end{concept}

\subsection{content\_and\_artifact (fuentes para la UI)}
\begin{lstlisting}
@tool(response_format="content_and_artifact")
def retrieve_context(query: str):
    """Retrieve relevant documentation..."""
    docs = vectorstore.as_retriever().invoke(query, k=4)
    serialized = "\n\n".join(
        f"Source: {doc.metadata.get('source')}\n\nContent: {doc.page_content}"
        for doc in docs)
    return serialized, docs  # (texto para LLM, artifact para UI)
\end{lstlisting}

En \texttt{run\_llm}: recorre \texttt{response["messages"]}, si es \texttt{ToolMessage} con \texttt{.artifact}, recoge los \texttt{Document}s.

\subsection{bind\_tools}
\begin{lstlisting}
llm_with_tools = llm.bind_tools(tools)
ai = llm_with_tools.invoke(messages)
# ai.tool_calls -> [{"name", "args", "id"}, ...]
\end{lstlisting}

Native function calling: estructura tipada, no texto ``Action: \ldots'' parseado a mano.

\section{Agents: tres niveles}
% =============================================================================

\subsection{A --- ReAct ``a mano'' (prompt + regex)}
\texttt{03/.../react-prompt-function-calling.py}

\begin{itemize}[leftmargin=*,itemsep=1pt]
  \item Prompt Thought / Action / Action Input / Observation / Final Answer
  \item Tools = funciones normales (+ \texttt{@traceable})
  \item Parseo con \texttt{regex}; \texttt{stop=["\textbackslash nObservation"]} para que el modelo no invente la Observation
  \item \textbf{Scratchpad}: se concatena \texttt{output + Observation + Thought:} al prompt
  \item Descripciones de tools vía \texttt{inspect.signature} + docstring
\end{itemize}

\begin{tip}
Útil para \emph{entender} agents. En producción: tool calling nativo (B/C).
\end{tip}

\subsection{B --- Loop + tool calling nativo}
\texttt{03/.../agent-loop-tool-calling.py}

\begin{enumerate}[leftmargin=*,itemsep=1pt]
  \item \texttt{llm\_with\_tools.invoke(messages)}
  \item Sin \texttt{tool\_calls} $\to$ respuesta final
  \item Con $\to$ ejecutar tool $\to$ append \texttt{AIMessage} + \texttt{ToolMessage}
  \item Hasta \texttt{MAX\_ITERATIONS} (aquí 5)
\end{enumerate}

El curso fuerza \textbf{una tool por iteración} (\texttt{tool\_calls[0]}) para controlar el orden: precio $\to$ descuento $\to$ shipping.

Reglas críticas van en el \texttt{SystemMessage}: no inventar precios, no calcular a mano, orden fijo, países desconocidos $\to$ \texttt{"Other"}.

Catálogo didáctico: laptop\,999, smartphone\,699, headphones\,199;
descuento bronze/silver/gold = 5/10/12\,\%;
shipping USA/Canada/Europe/Other = 5/10/15/20.

\section{LCEL y el operador \texttt{|}}
% =============================================================================

\textbf{LCEL} = LangChain Expression Language. Runnables compuestos como pipe Unix.

\begin{fromcode}[title=04-rag/main.py]
\begin{lstlisting}
from operator import itemgetter
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser

retrieval_chain = (
    RunnablePassthrough.assign(
        context=itemgetter("question") | retriever | format_docs
    )
    | prompt_template
    | llm
    | StrOutputParser()
)
answer = retrieval_chain.invoke({"question": query})
\end{lstlisting}
\end{fromcode}

Lectura:
\begin{enumerate}[leftmargin=*,itemsep=1pt]
  \item Entrada \texttt{\{"question": "..."\}}
  \item \texttt{assign} copia el dict y añade \texttt{context}:
        \texttt{question} $\to$ retriever $\to$ docs $\to$ \texttt{format\_docs} (string)
  \item Prompt rellena \texttt{\{context\}} y \texttt{\{question\}}
  \item LLM + \texttt{StrOutputParser()} $\to$ string final
\end{enumerate}

Beneficios vs imperativo: \texttt{stream}/\texttt{ainvoke}/\texttt{batch} gratis, más componible, mejor observabilidad.

Piezas frecuentes: \texttt{ChatPromptTemplate.from\_template}, \texttt{RunnablePassthrough.assign}, \texttt{itemgetter}, \texttt{StrOutputParser}.

% =============================================================================
\section{RAG: Retrieval-Augmented Generation}
% =============================================================================

\begin{concept}[title=Idea]
Ingesta docs $\to$ chunks $\to$ embeddings $\to$ vector store.
En query: recupera vecinos $\to$ contexto en el prompt $\to$ LLM responde \emph{basado en eso}.
\end{concept}

\subsection{Pipeline de ingestión}
\begin{center}
\texttt{Loader} $\to$ \texttt{TextSplitter} $\to$ \texttt{Embeddings} $\to$ \texttt{VectorStore.from\_documents} / \texttt{aadd\_documents}
\end{center}

\subsubsection{Loaders}
\begin{lstlisting}
from langchain_unstructured import UnstructuredLoader
loader = UnstructuredLoader(file_path="mediumblog1.txt",
    chunking_strategy="basic", max_characters=1000, encoding="UTF-8")

from langchain_community.document_loaders import PyPDFLoader
docs = PyPDFLoader("HuckFinn.pdf").load()  # List[Document]
\end{lstlisting}

\texttt{Document} = \texttt{page\_content} + \texttt{metadata} (p.ej.\ \texttt{source}, página).

\subsubsection{Splitters}
\begin{lstlisting}
CharacterTextSplitter(chunk_size=1000, chunk_overlap=0)          # 04 txt
RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50) # 04 PDF
RecursiveCharacterTextSplitter(chunk_size=4000, chunk_overlap=200) # 05 crawl
\end{lstlisting}

\begin{itemize}[leftmargin=*,itemsep=1pt]
  \item \texttt{chunk\_size}: tamaño objetivo
  \item \texttt{chunk\_overlap}: no cortar ideas a mitad
  \item Recursive: corta por párrafos/frases (mejor calidad habitual)
\end{itemize}

En 05 a veces aparece \texttt{from langchain\_classic.text\_splitter import RecursiveCharacterTextSplitter}
(alias de compatibilidad); el concepto es el mismo.

\subsubsection{Vector stores}
\begin{center}
\begin{tabular}{@{}llp{6.6cm}@{}}
\toprule
 & \textbf{Pinecone} & \textbf{Chroma} \\
\midrule
Dónde & Nube & Local (\texttt{persist\_directory}) \\
Key & \texttt{PINECONE\_API\_KEY} & No \\
Curso & 04-rag; opción en 05 & 05 (activo en código) \\
API & \texttt{PineconeVectorStore} & \texttt{Chroma(...)} \\
Índice & \texttt{os.environ["INDEX\_NAME"]} & carpeta \texttt{chroma\_db} \\
\bottomrule
\end{tabular}
\end{center}

\begin{lstlisting}
# Escribir
PineconeVectorStore.from_documents(texts, embeddings,
                                   index_name=os.environ["INDEX_NAME"])

# Leer
vectorstore = PineconeVectorStore(index_name=..., embedding=embeddings)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})
docs = retriever.invoke(query)

# 05 local
vectorstore = Chroma(persist_directory="chroma_db",
                     embedding_function=embeddings)
\end{lstlisting}

\texttt{k} = vecinos a devolver. Más $k$ $\neq$ siempre mejor (ruido + tokens).

\texttt{05/consts.py}: \texttt{INDEX\_NAME = "langchain-docs-2025"} (nombre sugerido si usas Pinecone en 05; el código activo usa Chroma).

\subsubsection{Batches y rate limits (\texttt{ingest-pdf.py})}
Google embeddings: lotes de 90 + \texttt{time.sleep(60)} entre batches para no pegar rate limit.
En 05: \texttt{asyncio.gather} sobre \texttt{aadd\_documents} por batch.

\subsubsection{Prompt RAG típico}
\begin{lstlisting}
"""Answer the question based only on the following context:

{context}

Question: {question}

Provide a detailed answer:"""
\end{lstlisting}

``based only on the following context'' reduce inventar fuera del retrieval.

\subsection{RAG simple vs agentic}

docs = PyPDFLoader(path).load()
chunks = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=50).split_documents(docs)
PineconeVectorStore.from_documents(chunks, embeddings, index_name=INDEX)
\end{lstlisting}

\subsection{4. RAG chain LCEL}
\begin{lstlisting}
chain = (
    RunnablePassthrough.assign(
        context=itemgetter("question") | retriever | format_docs)
    | prompt | llm | StrOutputParser())
chain.invoke({"question": "..."})
\end{lstlisting}

\subsection{5. Retrieval como tool}
\begin{lstlisting}
@tool(response_format="content_and_artifact")
def retrieve_context(query: str):
    docs = vectorstore.as_retriever().invoke(query, k=4)
    return serialize(docs), docs

agent = create_agent(model, tools=[retrieve_context], system_prompt=...)
\end{lstlisting}

\section{Errores mentales frecuentes}
% =============================================================================

\begin{enumerate}[leftmargin=*,itemsep=2pt]
  \item Confundir \textbf{LLM} (texto) con \textbf{embeddings} (vectores).
  \item Olvidar \texttt{load\_dotenv()} $\to$ ``missing API key''.
  \item Preguntar a Pinecone/Chroma \textbf{sin haber ingerido}.
  \item Embedding / dimensión distinta en ingest vs query.
  \item Docstring pobre en \texttt{@tool} $\to$ tool mal llamada.
  \item Esperar citas sin pedirlas en system prompt y/o sin pasar \texttt{metadata.source}.
  \item ReAct texto vs tool calling: parsear ``Action:'' es frágil.
  \item Input del agent: casi siempre \lstinline|{"messages": [...]}|, no un string suelto.
  \item Índice Pinecone con dim distinta a \texttt{output\_dimensionality} de Google emb.
  \item Rate limits (Google): batch + sleep; no mandar miles de chunks de golpe.
  \item En 05, cwd importa: \texttt{persist\_directory="chroma\_db"} es relativo a dónde lanzas el script.
\end{enumerate}
